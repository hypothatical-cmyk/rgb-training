# ChromaShift 레슨 앱 인수인계 (Google AI Studio용 프롬프트)

> 사용법: 이 문서 전체를 AI Studio 프롬프트에 붙여넣으세요. 함께 받은 `index.html`(작동하는 프로토타입)을 같이 첨부하면 그대로 이어서 개발할 수 있습니다. 첨부하지 않아도 이 문서만으로 다시 만들 수 있도록 공식과 문제 규칙을 모두 적어두었습니다.

## 0. 너에게 맡기는 일

포토샵의 RGB 채널 보정과 레이어 블렌딩 모드를 **감이 아니라 계산과 추론으로** 쓰게 만드는 학습 웹앱을 개발한다. 형식은 듀오링고처럼 짧은 레슨을 단계별로 여는 방식이다.

- 기존 프로토타입(`index.html`)이 첨부되어 있으면 **그 구조와 문제 생성 로직을 유지한 채** 개선한다. 처음부터 다시 쓰지 않는다.
- 첨부가 없으면 아래 명세대로 새로 만든다.
- 결과물은 React(또는 단일 HTML) 웹앱. 외부 서버 없이 브라우저만으로 동작하고, 진행 상황은 localStorage에 저장한다.

## 1. 핵심 설계 원칙 (가장 중요)

1. **예측하고 계산하는 문제가 중심이다.** 슬라이더를 움직여 눈으로 맞추는 문제는 감각 훈련이라 목표와 맞지 않는다. "아래 200, 위 128, Multiply 결과는?"처럼 답을 먼저 생각하게 한다.
2. **피드백에는 항상 '왜'를 보여준다.** 정답이든 오답이든 계산식을 그대로 보여준다. 예: `200 × 128 ÷ 255 ≈ 100`.
3. **레슨 하나는 약 2분이다.** 6~7문제. 앉으면 끝나는 단위가 있어야 앱을 다시 연다.
4. **문제는 매번 새로 만든다.** 숫자를 랜덤으로 생성하고, 정답과 보기는 공식으로 계산한다. 하드코딩된 문제를 외워서 푸는 일이 없어야 한다.
5. **중립색을 기준으로 생각하게 한다.** 모든 블렌딩 모드는 "칠해도 변화 없는 색"(흰색, 검정, 50% 회색)으로 그룹이 나뉜다. 이 사고법을 반복해서 익히게 한다.
6. **틀린 문제는 레슨 끝에 다시 낸다.** 하트나 목숨처럼 벌을 주는 장치는 넣지 않는다.

## 2. 화면 구조

### 2-1. 홈 (학습 경로)
- 상단 바: 로고, 연속 학습일(불꽃 아이콘), 총 XP
- **오늘의 목표** 카드: 하루 30 XP 진행 바 + "빠른 복습" 버튼(완료한 레슨에서 섞어 8문제, 완료 레슨이 없으면 비활성)
- 유닛별 헤더 카드(유닛 번호, 부제, 한 줄 설명, 유닛 고유 색 띠)
- 레슨 노드: 원형 버튼을 지그재그로 배치(sin 곡선으로 좌우 오프셋). 상태는 세 가지
  - 완료: 유닛 색 + 체크 아이콘, 다시 풀 수 있음
  - 현재: 유닛 색 + 재생 아이콘 + 위에 통통 튀는 "시작" 말풍선, 로드 시 화면 중앙으로 스크롤
  - 잠김: 회색 + 자물쇠, 누를 수 없음
- 레슨은 순서대로 하나씩 열린다.

### 2-2. 레슨
- 상단: 나가기(×) + 진행 바(맞힌 문제 수 / 전체)
- 첫 화면은 **규칙 카드**: 제목, 공식(고정폭 글꼴), 핵심 3줄, 중립색 견본. 버튼 문구는 "알겠어요, 풀어볼게요". 빠른 복습에서는 규칙 카드를 생략한다.
- 문제 화면: 레슨 이름 태그 → 질문 → 시각 자료 → 보기 → 하단 고정 "확인" 버튼
- 확인 후 하단 피드백 시트
  - 정답: 초록 배경, "정확해요" 류의 짧은 문구 + 해설
  - 오답: 빨간 배경, "다시 생각해 봐요" + `정답: …` + 해설
  - 필요하면 보정 전/후 이미지를 시트 안에 보여준다.
  - "계속" 버튼
- 다시 나온 문제에는 "다시 풀기" 표시를 붙인다.
- 키보드: 숫자 1~4로 보기 선택, Enter로 확인/계속

### 2-3. 완료 화면
- R·G·B 막대가 솟는 짧은 애니메이션
- 타일 3개: 획득 XP / 첫 시도 정답률 / 연속 학습일
- 틀렸다가 다시 풀고 넘어온 문제 수 안내
- "계속하기"(홈으로), "같은 레슨 새 문제로 다시"

### 2-4. 점수 규칙
- 레슨 완료 +10 XP, 첫 시도에 맞힌 문제당 +2 XP
- 연속 학습: 마지막 학습일이 어제면 +1, 오늘이면 유지, 그 외에는 1부터 다시
- 저장 키: `chromashift-lessons-v1` → `{done:{레슨id:true}, xp, streak, last, dayXp, day}`. localStorage는 try/catch로 감싸고, 없어도 앱이 동작해야 한다.

## 3. 문제 유형

| 유형 | 설명 |
|---|---|
| 선택형 (텍스트) | 보기 4개, 한 칼럼 |
| 선택형 (숫자) | 보기 4개를 2×2로, 고정폭 숫자 |
| 선택형 (색 견본) | 견본 + 이름/값 표기, 2×2 |
| 채널 스위치 | R·G·B 각 행에서 단계 버튼(0/255 또는 0/128/255)을 눌러 목표 색 만들기. 목표 견본과 "내가 만든 색" 견본을 나란히 보여주고 값도 표시. 정확히 일치하면 정답 |
| 모드 판별 | 아래/위/결과 캔버스 3장을 보고 블렌딩 모드 고르기 |
| 상황형 | 작업 상황 문장을 읽고 알맞은 모드 고르기 |

### 숫자 보기 만드는 규칙
- 오답 후보는 "흔히 헷갈리는 다른 모드의 계산값"을 우선 쓴다. 예: Multiply 문제의 오답은 min(a,b), Linear Burn, Screen, 평균
- 모든 보기는 서로 8 이상 차이 나야 한다. 부족하면 정답 ±14~80 범위에서 랜덤으로 채운다.
- 색 견본 보기는 RGB 값이 서로 달라야 한다(같은 색이 두 번 나오면 다른 모드로 교체).

## 4. 블렌딩 공식 (채널값 0~1, a=아래, b=위)

```
Multiply      a*b
Screen        1-(1-a)(1-b)
Darken        min(a,b)
Lighten       max(a,b)
Color Burn    a>=1 ? 1 : b<=0 ? 0 : max(0, 1-(1-a)/b)
Linear Burn   max(0, a+b-1)
Color Dodge   a<=0 ? 0 : b>=1 ? 1 : min(1, a/(1-b))
Linear Dodge  min(1, a+b)
Overlay       a<=.5 ? 2ab : 1-2(1-a)(1-b)
Hard Light    b<=.5 ? 2ab : 1-2(1-a)(1-b)
Soft Light    b<=.5 ? a-(1-2b)a(1-a)
                    : a+(2b-1)(D(a)-a),  D(a)= a<=.25 ? ((16a-12)a+4)a : sqrt(a)
Difference    |a-b|
Exclusion     a+b-2ab
```
비분리 모드(W3C 방식):
```
Lum(c) = 0.30R + 0.59G + 0.11B
SetLum(c,l): d=l-Lum(c); c+=d; ClipColor(c)
ClipColor: n=min, x=max, l=Lum
  n<0 → c = l + (c-l)*l/(l-n)
  x>1 → c = l + (c-l)*(1-l)/(x-l)
Color      = SetLum(위, Lum(아래))
Luminosity = SetLum(아래, Lum(위))
```
결과는 ×255 후 반올림하고 0~255로 자른다.

## 5. 커리큘럼 (7유닛 14레슨)

각 레슨: **규칙 카드** → 랜덤 생성 문제 6~7개(순서 섞기).

### UNIT 1 · 빛의 덧셈 (가산혼합 RGB) — 색 #d94a4a
**L1 세 채널 켜고 끄기**
- 규칙: RGB는 물감이 아니라 빛이다. 0=꺼짐, 255=완전히 켜짐. 빨강+초록=노랑, 초록+파랑=시안, 빨강+파랑=마젠타. 셋 다 켜면 흰색, 다 끄면 검정.
- 문제: ① R·G·B 값 칩만 보고 색 견본 고르기 ×3 (8가지 기본색 중) ② 채널 스위치(0/255)로 지정한 색 만들기 ×3
- 해설 예: "빨강 + 초록 빛 → 노랑. 빛은 더할수록 밝아져요."

**L2 중간값과 치우침**
- 규칙: R=G=B면 무채색. 128은 반쯤 켜진 빛(255,128,0 = 주황). 한 채널만 튀면 그 색 기운, 한 채널만 모자라면 반대색 기운.
- 문제: ① 채널 스위치(0/128/255)로 주황·분홍·보라·중간 회색·하늘색·어두운 빨강·연노랑·연두 중 3개 ② 값만 보고 어느 쪽으로 치우쳤는지 ×3 ③ 세 값이 같은 회색 1개
- 치우친 값 생성: 기준 n(110~170), 차이 d(16~30). 한 채널이 높은 경우 그 채널=n+d, 나머지=n−d/3. 한 채널이 낮은 경우 그 채널=n−d, 나머지=n+d/3.

**L3 반대색(보색) 짝**
- 규칙: 빨강↔시안, 초록↔마젠타, 파랑↔노랑. 흰색에서 Blue를 빼면 R+G = 노랑. 그래서 노란 기를 빼려면 Blue를 올린다.
- 문제: ① "커브에서 Blue 내리기 → 어느 쪽으로?" ×2 ② "노란 기가 돈다, 채널 하나만 만진다면?" ×2 ③ "빨강의 반대색은?" 견본 ×2

### UNIT 2 · 채널로 색 보정 (커브와 정보 패널) — 색 #d9a13a
**L4 캐스트 읽기**
- 규칙: 눈은 금방 적응하니 정보 패널 숫자로 판단한다. 원래 무채색이어야 할 곳(회색 카드, 흰 벽, 아스팔트)을 찍고, 가장 튀는 채널을 찾는다.
- 문제: ① 캐스트가 걸린 장면 이미지 + 정보 패널 값 → 어떤 캐스트인지 ×4 ② "스포이드는 어디에 찍어야 하나?" → 원래 회색·흰색이어야 할 곳
- 장면(230×144 캔버스): 하늘 그라데이션, 땅, 가운데 128 회색 카드(흰 테두리), 흰 패치, 검은 패치. 캐스트는 채널마다 (카드값/128)을 곱해서 적용.

**L5 커브로 중립 맞추기**
- 규칙: 카드가 R150 G128 B128이면 Red 커브에서 입력 150 → 출력 128. 목표는 R=G=B.
- 문제: ① 장면을 보고 바로잡는 가장 직접적인 방법 고르기 ×3(피드백에 전/후 이미지) ② "Red 커브에서 입력 150을 출력 몇으로?" ×3 (정답 = 나머지 두 채널 값)

### UNIT 3 · 어둡게 그룹 (Multiply · Darken · Burn) — 색 #9c6bd6, 중립색 흰색
**L6 Multiply**
- 규칙: `결과 = 아래 × 위 ÷ 255`. 흰색을 곱하면 그대로, 검정은 0. 결과는 항상 둘 중 어두운 쪽 이하. 채널별로 계산.
- 문제: 회색값 계산 ×3, 중립색 고르기, 컬러 두 장 Multiply 결과 견본 고르기, 상황형(선화 흰 배경 제거)

**L7 Darken · Burn**
- 규칙: Darken = 채널별 min이라 두 색 어디에도 없던 새 색이 나올 수 있다. Linear Burn = 아래+위−255. Color Burn은 대비를 세게 올리며 어둡게 한다.
- 문제: 컬러 Darken 결과(채널별 min으로 새 색이 나오도록 값 설계), Linear Burn 계산 ×2, Darken 계산, "같은 값에서 가장 어두운 모드는?"(4개 모드를 실제 계산해서 1등과 2등 차이 6 이상일 때만 출제), 상황형

### UNIT 4 · 밝게 그룹 (Screen · Lighten · Dodge) — 색 #3fa6c9, 중립색 검정
**L8 Screen**
- 규칙: `결과 = 255 − (255−아래)(255−위) ÷ 255`. Multiply의 거울. 검정이 중립. 결과는 항상 밝은 쪽 이상.
- 문제: 계산 ×3, 중립색, "밝은 쪽과 비교하면?", 상황형(검은 배경 불꽃 합성)

**L9 Lighten · Dodge**
- 규칙: Lighten = max. Linear Dodge(Add) = 단순 덧셈이라 255를 넘으면 하얗게 날아감. Color Dodge는 대비가 크다.
- 문제: Add 계산 ×2, Lighten 계산, "가장 밝은 모드는?", 상황형(빛 번짐), "Screen과 Add 중 더 쉽게 날아가는 쪽?"(128+128 예시)

### UNIT 5 · 대비 그룹 (Overlay · Soft · Hard Light) — 색 #4fae6a, 중립색 50% 회색
**L10 Overlay 계열**
- 규칙: 아래가 128 미만이면 `2×아래×위÷255`(곱하기 쪽), 128 이상이면 `255 − 2(255−아래)(255−위)÷255`(스크린 쪽). Hard Light는 같은 식을 위 레이어 기준으로. Soft Light는 같은 방향이지만 훨씬 약하다.
- 문제: Overlay 계산 ×3(첫 문제는 아래가 어두운 값, 나머지는 밝은 값. 해설에 어느 분기인지 명시), 중립색, Overlay vs Hard Light 차이, "50% 회색 Overlay 레이어에 흰 브러시로 칠하면?", 상황형(닷지·번 레이어)

### UNIT 6 · 비교와 성분 (Difference · Color · Luminosity) — 색 #c9579a
**L11 Difference**
- 규칙: `|아래 − 위|`. 같으면 검정(정렬 확인용). 검정이 중립, 흰색은 반전.
- 문제: 계산 ×3, 흰색 레이어 올렸을 때 결과(반전 견본), 같은 레이어 두 장을 겹치면, 상황형(정렬)

**L12 Color · Luminosity**
- 규칙: Color = 아래 밝기 + 위 색. Luminosity = 아래 색 + 위 밝기. 광도 ≈ 0.30R+0.59G+0.11B. 순수 파랑은 생각보다 어둡다.
- 문제: "그레이스케일로 바꾸면 가장 밝게/어둡게 남는 색" 각 1(1등과 2등 광도 차이 15 이상), Color 결과 견본 고르기, 상황형(흑백 채색 → Color, 샤프닝 색 테두리 → Luminosity)

### UNIT 7 · 실전 — 색 #7f8cff
**L13 모드 맞히기**
- 규칙: 위 레이어는 검정·50% 회색·흰색·색 네 줄. 어느 줄 자리가 그대로인지 보면 중립색이 보이고, 중립색이 그룹을 알려준다.
- 캔버스(150×104 ×3): 아래 = 가로 색상환(0~360°), 세로 명도(위 밝음→아래 어두움), 채도 0.75. 위 = 세로 4줄 [0,0,0] [128,128,128] [255,255,255] [랜덤 색]. 결과 = 실제 블렌딩 계산.
- 출제 모드: Multiply, Screen, Overlay, Darken, Lighten, Difference, Color Burn, Linear Dodge, Luminosity 중 6개
- 해설은 모드별 단서. 예: Multiply "흰 줄 자리는 그대로, 검은 줄 자리는 새까맣다", Difference "흰 줄 자리가 반전된다"

**L14 상황에 맞는 모드**
- 규칙: 무엇을 없애고 싶은지 먼저 생각한다(흰색→어둡게 그룹, 검정→밝게 그룹, 회색→대비 그룹). 그 다음 세기를 고른다.
- 상황 9개 중 6개 출제:
  1. 스캔한 선화의 흰 바탕 제거 → Multiply (오답: Screen, Overlay, Difference)
  2. 검은 배경 불꽃 소스 합성 → Screen (Multiply, Darken, Color)
  3. 두 사진 픽셀 정렬 확인 → Difference (Overlay, Multiply, Luminosity)
  4. 50% 회색 닷지·번 레이어 → Overlay (Multiply, Screen, Normal)
  5. 흑백 사진 채색 → Color (Luminosity, Multiply, Screen)
  6. 샤프닝 색 테두리 방지 → Luminosity (Color, Overlay, Difference)
  7. 강한 빛 번짐, 하얗게 날아가도 됨 → Linear Dodge (Screen, Lighten, Soft Light)
  8. 채널마다 더 어두운 값만 남기기 → Darken (Multiply, Linear Burn, Difference)
  9. 종이 질감을 아주 은은하게 → Soft Light (Hard Light, Color Burn, Linear Dodge)

## 6. 디자인

- **배경은 완전 중립 회색**(#2b2b2b, R=G=B). 색 판단을 흐리지 않도록 포토샵 작업창처럼 둔다. 이 앱의 정체성이니 바꾸지 않는다.
- 패널 #363636, 선 #474747, 글자 #ececec, 보조 글자 #a3a3a3
- 강조 #4ea4ff, 정답 #3fcf7d, 오답 #ff5d61
- 채널 색 R #ff4f4f, G #37d67a, B #4d8dff
- 글꼴: 본문 IBM Plex Sans KR, 숫자·공식 IBM Plex Mono(tabular-nums)
- 모바일 우선, 최대 폭 560px 한 칼럼. 400px 이하에서는 2×2 보기를 1열로.
- 버튼은 아래 테두리를 두껍게 해 눌리는 느낌을 준다(듀오링고식). 하단 확인 버튼은 sticky.
- prefers-reduced-motion이면 애니메이션을 끈다. 포커스 링이 보여야 한다.
- 문구는 짧고 존댓말("~해요"). 이모지는 쓰지 않는다.

## 7. 완료 전에 반드시 확인할 것

- [ ] 새로고침 후 진행 상황 유지, localStorage를 막아도 오류 없이 동작
- [ ] 휴대폰 폭(390px)에서 캔버스 3장, 보기, 하단 버튼이 잘리지 않음

## 8. 하지 말 것

- 슬라이더로 눈대중 맞추기를 주된 문제 유형으로 만들지 말 것
- 하트·목숨처럼 틀리면 레슨이 막히는 장치를 넣지 말 것
- 해설 없이 정답/오답만 알려주지 말 것
- 문제를 고정 데이터로 하드코딩하지 말 것(상황형 문장만 예외)
- 배경을 유채색이나 그라데이션으로 바꾸지 말 것
